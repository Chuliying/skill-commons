skill-commons

把交付流程的形狀固定下來：每一步產出形體一致、可續跑、可被 script 驗證的 artifact。 這頁由 repo 的機器來源生成，權威在 repo，此頁只是索引——每個細節都以一個檔案連結收尾。

它是宣告式契約加一致性檢查，不是 runtime engine、不是 state machine、不是 scheduler。

為什麼是這個形狀

人只停在三個判斷點：需求、設計取捨、發布。其餘一律機器檢查，缺件與無法界定時停下來，不猜測後繼續。

怎麼運作

24 個技能依 flow 派發，artifact 契約由 protocol registry 宣告，狀態落在檔案而非對話。

怎麼用

在 .agent/project-manifest.md 設 delivery_mode（personal 或 team-sprint）與選用的 capability_packs（frontend、optional），再跑 bootstrap/onboard.sh 重新 fan-out。execution mode 由 router 依單一任務決定，不必手動設定。

怎麼驗

26 條確定性 suite 加真 agent journey；完成宣稱必須附當次證據。
